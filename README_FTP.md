# Nebula ISO2GOD — optional FTP upload

This build includes a local Python helper for FTP because a browser on GitHub Pages cannot open raw FTP connections. The helper serves the page at `http://127.0.0.1:8765/` and connects from your computer to your Xbox.

## Start it (Windows, macOS, or Linux)

1. Install Python 3 if it is not already installed.
2. Keep `index.html` and `ftp_helper.py` together in the same folder.
3. Run `python3 ftp_helper.py` (Windows may use `py ftp_helper.py`). Keep the terminal open. The helper opens its local page automatically; otherwise visit `http://127.0.0.1:8765/`.
4. On the Xbox 360, enable the FTP server in Aurora or FreeStyle Dash and note the console's LAN IP, FTP port, username, and password.
5. In the ISO FTP setup, the primary destination preset is the confirmed USB1 Content folder (`Usb1:/Content/0000000000000000/`, shown by the dashboard as `/Usb1/Content/0000000000000000/`). Selecting it writes game packages directly under the existing Content root without duplicating `Content/0000000000000000`. The HDD1/USB0/USB1 root presets instead build the full Content path automatically; choose a custom path if your dashboard exposes a different drive name. Then test the FTP connection.

## Import a .7z archive locally

In the **Convert an ISO** task, choose **Choose .7z archive(s)…** or drop multiple `.7z` archives into the ISO drop zone. You may mix archives with loose ISO images in the same selection/drop. The page processes archives sequentially in a Web Worker and extracts only entries ending in `.iso`, `.xiso`, `.xsf`, `.img`, or `.bin`; other archive entries are not extracted. Images from every archive and the loose files are combined into one queue. The original archives on your computer are left unchanged, and no archive/image data is uploaded during extraction. Extracted images stay in the browser's Origin Private File System (OPFS) while needed for conversion and any FTP retry. After a successful conversion/batch, the app removes temporary extractions automatically. It also cleans up on a new import, reset, failure, or page exit.

Use a recent Safari, Chrome, or Edge browser on a secure origin (GitHub Pages HTTPS or the local helper at `http://127.0.0.1:8765/`); do not open `index.html` directly as a `file://` URL. The local helper serves the bundled module-worker and WASM files from `vendor/`, which are needed for the browser-only extractor. Keep `vendor/un7z-opfs/` next to `index.html` and `ftp_helper.py`. The browser needs available site storage for the extracted image and memory for the 7z decompressor; large dictionaries/archives can exceed browser limits. Password-protected or damaged archives are not supported. `.zip` is not accepted by this importer. If an archive contains several supported images, they are queued sequentially. Multi-ISO batches support one user-chosen output folder, one combined ZIP, or Xbox FTP.

When deploying the website, keep `vendor/un7z-opfs/` (including its worker, WASM binary, and license) next to `index.html`; the page loads these files locally. No npm install or network service is needed at runtime.

## Browse and manage files on the Xbox

Open **Xbox FTP file manager** at the top of the locally served app. Its **Download Mac one-tap helper** button stays visible whenever the FTP manager page is open; use it to download the updated fixed Mac launcher ZIP, unzip it, and open `Nebula ISO2GOD.command` (Python 3 is required). Connect with the console's FTP host, port, username, password, and a starting drive/path exposed by Aurora or FreeStyle Dash (for example `Hdd1:/` or `Usb0:/`). A non-empty starting path is sent to the FTP server exactly as entered (including capitalization); a blank field defaults to `Hdd1:/`. Use the exact syntax your dashboard accepts. Press **Enter** in any connection field to attempt connecting and browse, or click **Connect & browse**. The manager lists the folders and files below that starting path; open folders and use **Back**, **Forward**, breadcrumbs, or **Up** to navigate. Empty folders are openable and remain writable: the listing says when one is empty, while **Upload files**, **Upload folder**, and the drop area target the currently open folder. If an empty directory is not shown in the server listing, enter its relative path under the starting folder in **Open folder path** (for example `folder/subfolder`) and choose **Open folder**; this directly checks and opens that path. The history arrows appear immediately above the file listing, remain clickable while connected, and show a hint at the start/end of the visited-folder history. A free-space indicator appears beside the remote location only if the FTP server supports the optional `AVBL` command; ordinary FTP does not guarantee storage-capacity reporting, so unsupported servers show “not reported.” **Search this folder** filters the currently listed names (it does not scan subfolders); changing the search clears the current selection to prevent actions on hidden results. Uploading shows a blue/cyan progress badge with item counts, deleting shows an amber badge and current item, success is green, and errors are red. Browsing never goes above the configured starting path. The static GitHub Pages site cannot browse FTP by itself—the local helper must be running and the page must be opened from its loopback address.

Click the remote `launch.ini` filename once to open it in the built-in UTF-8 editor, or select its checkbox and choose **Edit launch.ini** in the sticky action toolbar above the listing. Double-click any filename (including `launch.ini`) to rename the remote file; the helper checks for name collisions and never overwrites a same-named item. Saving editor changes requires a themed confirmation and overwrites the remote file; keep a backup first. The in-page editor is limited to 2 MiB and declines files that are not valid UTF-8. FTP manager confirmations, retry prompts, rename prompts, and folder-name dialogs use the site's dark Nebula theme.

Select multiple rows by clicking and holding a row checkbox while dragging across other checkboxes, or hold the blank edge/space of a row (outside its filename and buttons) and drag across rows to highlight or unhighlight them. Shift-click selects a contiguous range, and the select-all checkbox remains available. Remote file moves stay on the Xbox: drag a file row onto a folder row in the current listing. If you have selected multiple file rows, dragging one of those selected rows moves them together. The manager checks the destination and refuses same-name collisions rather than overwriting; moves are limited to a subfolder of the file’s current folder. A multi-file move can stop partway if the FTP server reports an error, so refresh and review the source/destination before retrying. To copy selected Xbox files directly into a local folder, choose **Copy to Desktop** and choose Desktop in the system folder picker (the picker starts at Desktop when supported). This uses the browser's folder-access API and is disabled in browsers that do not support it. **Import selected to computer** remains the compatible fallback: the browser saves the selected files to Downloads, from where you can move them to Desktop. For real desktop drag-out, Chromium-based Chrome/Edge on desktop is required: select one remote file up to 64 MiB, choose **Prepare drag-out**, then drag that row to the desktop within 15 minutes. The helper stages the actual bytes locally and serves them over a short-lived, unguessable HTTP URL; it does not make an empty placeholder. Safari/Firefox do not reliably support exporting file bytes from a page drag, so the button is disabled there. Use **Import** for those browsers, larger files, or batches.

Use **Upload files**, **Upload folder**, or drag PC files/folders into the dashed upload area. This is a general-purpose FTP file manager: any file type is uploaded byte-for-byte as selected, with no game-specific filtering or conversion; you can select or drop multiple ordinary files at once, and they upload sequentially in the selection/drop order. Folder uploads preserve their relative paths. Directly choosing or dropping one `.zip` or `.7z` archive unpacks it locally and uploads every safe regular file inside, preserving archive subfolders and file bytes. The original archive on your computer is unchanged. Archives contained inside an uploaded folder are uploaded as ordinary files. You can also drop onto an individual remote folder row to upload into that folder. Uploads preserve names and relative folder structure; a remote file with the same path may be replaced. To copy files from the Xbox to your Mac, open the remote folder and select one or more files. **Copy to Desktop** opens a system folder picker so you can choose Desktop; supported browsers may open the picker there by default. If that browser feature is unavailable, use **Import selected to computer**; the helper streams files to the browser without making an extra disk staging copy, and the browser saves them to Downloads (it may ask permission for multiple downloads). Open folders to reach files—folder downloads as a ZIP are not supported. **New folder** creates a directory at the current location and immediately opens it (including when it is empty), so the upload buttons and drop area are ready to add files there. Select files/folders and choose **Delete selected** to remove them. Deleting a folder is recursive and permanent; the manager deliberately does not allow deleting the configured starting/root folder. The helper validates path segments and rejects links or unknown items during recursive deletion, but use care around saves and system files.

The **Use for ISO → GOD / XBLA / PS1** shortcuts set the selected tool's FTP destination to the currently viewed folder and transfer the active helper connection to that tool. The ISO/XBLA tools create their normal `Content/…` structure below the chosen base; PS1 uploads go to that folder unless a subfolder is selected. Reconnect in the manager when returning to browse, because the helper uses one active FTP connection configuration at a time.

FTP is usually unencrypted. Use this only on a trusted local network. Never forward the Xbox FTP port from your router or expose it to the internet. The helper itself remains loopback-only on the Mac; the FTP connection from the helper to the Xbox travels over your LAN.

## Convert and send an ISO

Choose **Convert an ISO**, then choose **Upload to Xbox via FTP** in the output options, test the connection, and convert. Each generated GOD package file is staged on the computer and sent to the console. If FTP disconnects during a file, conversion pauses and offers **Retry file & continue**. Reconnect/check the Xbox and LAN, keep the page and helper open, then use that button; completed package files are kept and conversion continues after the failed file succeeds. FTP `STOR` retries the current file from its beginning (it is not byte-offset resume) and replaces any partial remote copy. If you cancel instead, remove the unconfirmed/partial file or package before starting over. Rescan the Content path in Aurora/FSD after the website reports a complete upload.

## Batch-convert multiple ISOs to a folder or over FTP

In **Convert an ISO**, select or drop several ISO files; the queue shows each filename and size. Choose **Save GOD to a folder** and pick one destination, **Download one ZIP** to package every selected ISO into a single archive, or **Upload to Xbox via FTP** and test the connection. Start the batch to analyze and convert each ISO sequentially—not in parallel. Folder mode writes every package into the same chosen destination, preserving the normal `Content/…` layout; the resulting GODs appear as separate packages. ZIP mode puts all packages under their normal `Content/…` paths in one ZIP; where the browser cannot save directly to a chosen file, the ZIP is assembled as a browser download, which can be memory-heavy for very large batches. FTP mode uploads each package before starting the next, so the Xbox/helper handles only one package at a time. A failed FTP file pauses that ISO and offers the retry action; successful retry continues the current ISO, then the next ISO runs sequentially. If you cancel or the local helper/staged file is no longer available, the batch stops; completed folder/FTP outputs remain, while an incomplete combined ZIP is discarded. Remove any unconfirmed partial package before retrying it.

The separate XBLA/XBLIG workflow accepts multiple content files from the selected Title ID/game folder and uploads them one after another, unchanged. During raw uploads, the overall bar tracks aggregate bytes across the entire selection while the separate blue bar and filename/bytes/speed line track the current Xbox file. It uses the same retry action if the FTP connection fails during a file.

## Send existing XBLA/XBLIG content unchanged

Choose the separate **Upload existing XBLA/XBLIG file(s)** task at the top of the page. First unzip the XBLA archive on your Mac. Then drop/select the game's **8-character Title ID folder** (such as `584111FF`) or its parent game folder; do not select the outer archive, only the `000D0000` folder, or an individual content file. The uploader finds files directly inside the matching `<TitleID>/000D0000/` folder (for example `Quantum Conundrum (World) (XBLA)/584111FF/000D0000/<content file>`) and detects the Title ID automatically.

Each selected file is sent without conversion, renaming, or repacking to:

`<FTP base>/Content/0000000000000000/<TitleID>/000D0000/<original filename>`

The helper creates missing folders. A file with the same name in that destination may be overwritten. Use the folder picker or drag the extracted Title ID/game folder; multiple files are queued and sent one at a time. During upload, the overall job bar tracks aggregate bytes across the selection, while the separate blue bar and filename/bytes/speed line track the current Xbox file. If FTP fails, keep this page, helper, and extracted source files available while you use **Retry file & continue**. After the upload reports complete, rescan Aurora.

## Merge PS1 multi-BIN games for PCSXR360

Choose **PS1 BIN merger for PCSXR360**, then select or drop an extracted PS1 game folder containing one `.cue` and every `.bin` track it references. To send the result directly to the console, choose **Upload to Xbox via FTP**, enter the dashboard FTP details, and test the connection. The base path is the HDD/USB root exposed by the dashboard. The separate Xbox folder field is optional: leave it blank to upload into that base path, or enter the folder PCSXR360 browses for games (for example, `Emulators/PCSXR360/games`). Missing folders are created automatically. Per-game subfolders are also optional.

Each disc is merged locally first. The helper stages one finished file at a time on the computer, then sends the merged `.bin`, its same-named `.cue`, and an optional matching `.sbi` to the Xbox. Keep each `.bin` and `.cue` together with exactly matching names. In PCSXR360, select the `.bin`; the emulator finds the matching `.cue` automatically for track/CD-audio information. Multi-disc games remain separate pairs and should be swapped with the emulator's disc-eject flow. The source folder is never modified. Merging is lossless and does not compress the game; only raw 2352-byte-sector BIN/CUE images are accepted for PCSXR360.

## Upload SNES ROMs to SNES360

Choose **SNES360 ROM uploader**. Add `.sfc`, `.smc`, `.swc`, or `.fig` ROM files by selecting them or dragging them into the drop area. You may also drop a folder: it is scanned recursively, only supported ROM files are accepted, and they are flattened into the chosen Xbox ROM folder (source folder names and unrelated files, including archives inside the folder, are ignored and not deleted from your computer). The numbered ROM list is the exact sequential FTP upload order; each complete ROM is copied byte-for-byte unchanged, with no conversion or repacking. FATX-valid names up to 42 characters are kept exactly; unsupported characters (such as `+`, comma, or colon) are replaced with hyphens, and longer Xbox destination names are shortened to the 42-character FATX limit while preserving the extension. The original Mac filename and source file are never changed, and adjusted-name collisions receive a small numeric suffix to avoid overwriting another selected ROM. Duplicate original destination filenames are skipped. A `.7z` archive may be selected or dropped one at a time. The browser extracts only those supported ROM extensions into temporary OPFS storage, skips readmes/metadata/other entries, and leaves the original archive untouched. Extracted data remains available for FTP retry, is deleted after successful upload or when the ROM list is cleared, and is swept on page exit/reload. Keep the page open while using retry.

The selected default destination is `usb1/emulators/Snes360/Roms`: FTP base path `usb1/` plus relative folder `emulators/Snes360/Roms`, as requested. This is a configurable destination, so ensure your SNES360 installation is set to scan/map that path; otherwise select a matching preset or enter the correct custom path. Other documented layouts include SNES360 v0.32 HDD `Hdd1:/Emus/Snes360/Roms/`, v0.32 USB0 `Usb0:/Roms/`, and older v0.21 USB `Usb0:/_Emus/Snes360/Roms/`. Both fields are editable; blank base defaults to `Hdd1:/`. The helper creates missing folders beneath the selected base. Files with an existing identical filename in the target folder may be overwritten.

FTP uploads require the local helper. This tab keeps the fixed Mac one-command launcher and helper bundle downloads available. Uploads run one ROM at a time; the blue bar reports current-file staging/FTP progress, and the list is retained if a file fails so it can be retried. On Xbox FATX destinations, unsupported filename characters are replaced and names longer than 42 characters are shortened only in the Xbox copy; the source filename and ROM bytes remain untouched.

## Important safety and limitations

- Use FTP only on a trusted home LAN. Xbox FTP is normally unencrypted. Do not enable router port forwarding or expose the console's FTP port to the public internet.
- The helper binds only to `127.0.0.1` (your own computer), not to your LAN. The optional “Remember Xbox IP and username” checkbox stores only those two values in the browser’s local storage on this Mac; the FTP password is never saved. The checkboxes on the ISO, XBLA, PS1, SNES360, and FTP manager panels share the same saved values.
- For ISO conversion, the ISO itself is never uploaded; only generated package files are sent to the Xbox.
- The helper stages one file at a time. Ensure temporary disk space is available for the largest file being sent (raw files may be much larger than a single GOD data part). A failed FTP file remains staged while Retry is available; success, cancel, or normal helper shutdown removes it, and the next helper launch sweeps abandoned staging files from a prior crash.
- The helper allows up to 180 seconds without FTP data before a transfer times out. Wired Ethernet and a stable USB/HDD connection can reduce stalls.
- FTP transfer does not make unsigned GOD packages boot on retail/unmodded consoles; the ISO-to-GOD path requires compatible JTAG/RGH setup.

If the FTP base path is rejected, use your dashboard's FTP configuration or an FTP client to confirm the exact root path, then enter it in the relevant panel.
