    💿 PS1 multi-BIN merger for PCSXR360

    Drop a PS1 game folder that contains one .cue plus several track files such as Game (Track 1).bin, Game (Track 2).bin… (the Redump layout), or drop a .7z archive containing those files. This tab merges them — losslessly, byte for byte — into one folder with a single .bin and its matching .cue, the pair PCSXR360 2.1.1b can load with CD audio. Your original game folder is left completely alone: nothing in it is changed or deleted. The new .cue keeps the same name as the original; inside it, only the FILE/TRACK/INDEX lines PCSXR360 actually reads are kept, with track positions recalculated for the single .bin (PCSXR360 ignores a cue’s FILE lines, so an unchanged multi-file cue would lose track positions and CD audio). Extra files in the source folder — covers, .md5/.ccd/.sub, readmes and similar — are not copied to the output. Choose a parent folder to queue several games at once; multi-disc games stay as one separate .bin/.cue pair per disc, and when all discs are dropped together, detected discs from the same game can automatically share one game folder in folder/FTP output.

    Merging is not compression. The merged .bin is the same total size as the track files combined (only the unneeded side files are left behind). Smaller formats such as CHD or PBP are not supported by PCSXR360 2.1.1b, so a plain .bin is what it needs. Only merge backups of games you own.

    Download the merged files

    Download each .bin together with the .cue of the same name and keep them side by side. In PCSXR360, select the .bin — the matching .cue beside it is read automatically for game info and CD audio. Any .bin.jpg cover download goes in the PCSXR360 folder’s covers folder instead.

    Loading it in PCSXR360 2.1.1b

    1. Put each merged .bin + same-named .cue pair in the folder you browse for games in PCSXR360 (by FTP above, or via USB + a file manager). Never separate or rename one without the other.
    2. In PCSXR360’s game list, select the .bin file. The .cue does not need to be selected — the emulator looks for a .cue with the same name beside the .bin and uses it for track layout and CD-audio music.
    3. Cover art: PCSXR360 looks for ExactGameName.bin.jpg in the covers folder inside the PCSXR360 emulator folder. FTP can put matched covers there directly; for folder/download output, copy the contents of PCSXR360-covers (or the cover JPG downloads) into that covers folder. A grouped game folder may still show PCSXR360’s generic folder icon until you open it and highlight the .bin.
    4. Multi-disc games: when all discs were selected together and grouping was on, their separate pairs are placed together in one game folder. Keep one pair per disc and swap with the in-game menu’s eject/change-disc option when the game asks for the next disc; don’t try to combine different discs into one .bin.
    5. No music in a CD-audio game usually means the .cue is missing, renamed, or in a different folder from the .bin.

    🔭 How it works, compatibility & troubleshooting

    What exactly is created? A Games on Demand SVOD package: a 44 KiB LIVE header (content type 00007000) plus a <container>.data folder of Data#### parts. The disc’s game partition is cut into 4 KiB blocks; every 204 blocks get a SHA-1 sub-hash table, every part starts with a master hash table, and those master tables are chained backwards so the console can verify the whole image from the single hash stored in the header. The game partition bytes themselves are copied verbatim — files are never repacked or moved — which is why games that care about on-disc layout keep working.

    Will it work on an unmodded/retail Xbox 360? No. Microsoft’s RSA private key signs real Marketplace GODs; Iso2God-style packages have a blank signature and only boot where signature checks are patched (JTAG/RGH with DashLaunch). That is a console restriction, not something any converter can bypass.

    Multi-disc games and install discs: playable discs stay separate GOD packages; recognized install/content discs are extracted to the console’s Content tree. The parser reads the XEX Title ID, Media ID, disc number/count, and XDVDFS tree. The bundled offline role source now uses the Redump Xbox 360 DAT dated 2026-10-30 (3,733 media entries); Vimm’s Vault, which says it syncs nightly with Redump, currently reports 3,714 of 3,733 media. The exact XEX identity crosswalk matches Title ID + Media ID against 2,577 records in the IronRingX game list. Role labels are joined by exact normalized game title + disc number; this build has 31 exact Media-ID role rules (16 playable, 15 install) across 13 title IDs, plus the separately researched Halo 4 Disc 1/2 rule. Redump/Vimm’s larger media count does not itself supply the XEX crosswalk or prove a disc’s role. The catalogue also recognizes game/disc names and regions where the source provides them, even if the disc role is unknown. This is broad partial coverage, not “any disc”: both upstream sources are incomplete, CSV rows without Media IDs cannot be exact-matched, and role labels can be ambiguous or absent. Any unknown or conflicting executable-disc role—including single-disc entries without role evidence—and executable-plus-Content layouts use the themed chooser, which shows the ISO filename. The app never decides a role from disc number alone; it also refuses GOD output when a known installer lacks an extractable Content tree. Placeholder folders such as Content/FFED2000/FFFFFFFF still need the paired game’s Title ID. Dropping a multi-disc set together applies checks to every ISO. Folder and ZIP keep outputs separate; FTP routes each item to its GOD or Content path. Some titles need game-specific layouts or swap plugins, which generic extraction does not configure. Keep the full game partition only avoids trimming an image; it does not unpack install content. The local generator and review report are included with the source build so catalogue updates can be checked before shipping.

    The game shows as corrupted / won’t launch:

    • Check every Data#### part copied and sizes match (all but the last are exactly 162.6 MiB / 0xA290000 bytes).
    • Make sure it is under Content\0000000000000000\<correct Title ID>\00007000\ — not an extra nested Content\Content.
    • Re-convert with full padding kept; a handful of titles dislike trimming.
    • Verify your source ISO is a clean rip (not already an extracted folder, a GOD, or a PC ISO9660 file).

    Browser notes: Chrome/Edge provide browser-native folder saving and streaming ZIPs. Safari on macOS can save directly to a chosen folder when opened through the updated local helper; otherwise Safari/Firefox use ZIP or individual downloads, which can be memory-hungry for multi-GB games. Conversion speed is mostly SHA-1 hashing on one CPU core plus your disk speed.

    Privacy: ISO analysis and conversion run in your browser; the page loads its bundled disc catalogue from the same site, but does not send your ISO or game files to a server. FTP upload is optional and requires the local helper; it sends completed GOD/content files to the Xbox over your home LAN. FTP credentials are held in helper memory only while it runs. Do not expose the Xbox FTP server to the public internet.

    Original Xbox games: images containing default.xbe are written as Xbox Original packages (00005000). Playing them still needs the console’s Xbox backwards-compatibility files/hacked compatibility partition — the GOD is only the container.

    PS1 BIN merger — what exactly happens to my game folder? Nothing: the merger only reads the folder you select. It concatenates the .bin track files in the order the .cue lists them (byte for byte, no re-encoding — the same merge the desktop binmerge tool performs) and writes a new single-FILE .cue with every INDEX position recalculated. Cue extras that the target emulator ignores (REM, catalog/CD-text, sub-indexes) and side files (checksums, covers, .ccd/.sub, readmes) are left out of the output. PREGAP/POSTGAP commands, which PCSXR360 ignores, are materialised as real silent sectors in the merged .bin so track positions stay correct.

    Why does PCSXR360 need a single .bin? PCSXR360 (2.1.1b) opens exactly one disc file. When you pick a .bin it derives the cue name from that file’s name (Game.bin → Game.cue) and reads only its TRACK/INDEX lines — the cue’s FILE lines are ignored. With a Redump multi-track folder, picking Game (Track 1).bin looks for a non-existent Game (Track 1).cue and the audio tracks in the other .bin files are never seen. A merged Game.bin + Game.cue is the layout it can actually use. It reads raw 2352-byte sectors, so 2048/2336-byte images are rejected here rather than merged into something the emulator would misread.

    Long PS1 file names: the Xbox 360 internal-HDD (FATX) file system limits names to 42 characters. The merger warns you when a game name exceeds that — such names still work from USB/FAT32, but shorten the output name in the list if an FTP copy to Hdd1 fails.

    PS1 cover art: online lookup is off by default. When enabled, the merger reads each disc’s serial locally (normally from SYSTEM.CNF) and asks the public xlenore/psx-covers collection on GitHub for that serial’s JPG; the serial is the only game-derived identifier sent (along with normal web-request metadata), and game files are never uploaded. You can also select local JPG, PNG, or WebP images, matched by game name or PS1 serial; local art is tried first and stays on this computer. Images are converted in-browser to a baseline JPG up to 512×512 named after the output .bin (for example Game.bin.jpg), as PCSXR360 2.1.1b expects in its emulator folder’s covers folder. Missing/unavailable covers are logged and skipped without affecting the game. This art appears inside PCSXR360 when the .bin is highlighted; it does not create Aurora artwork.
